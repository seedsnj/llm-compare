# 需求规格

- 最后更新：2026-11-06
- 文档版本：1.1.0

## 1. 产品目标

为 GitHub Copilot 用户提供一个纯前端模型选择面板，帮助用户同时理解：

- 模型的用量计费价格；
- 模型在真实开发难度分布中的相对能力；
- 成本与能力结合后的综合性价比；
- 五类日常开发任务下有哪些可信证据和推断限制。

产品只覆盖 GitHub Copilot AI Credits 用量计费，不考虑旧版年度套餐或订阅倍率。

## 2. 用户与使用场景

目标用户是需要在 GitHub Copilot 模型间做选择、成本评估或能力复核的开发者和技术负责人。

主要场景：

1. 快速找到便宜、能力足够或综合性价比高的模型。
2. 按模型名或供应商筛选候选模型。
3. 固定最多 3 个常看模型并在刷新后保留。
4. 查看某个模型在文档、架构、实现、测试和协作任务上的证据。
5. 手动刷新价格，同时保留离线可用的内置数据。

## 3. 范围

### 3.1 范围内

- GitHub Copilot 当前模型列表与已退役模型历史视图。
- $/1M token 的输入、输出和可选缓存输入价格。
- 参考会话成本与 AI Credits 换算。
- 高难度、通用开发、日常信息三维 Profile。
- 综合性价比排序和「值选」标识。
- AA、LMArena 等能力证据与五类任务预测。
- 文本过滤、排序、Pin、手动价格刷新和 localStorage 缓存。
- 响应式桌面与移动布局。

### 3.2 范围外

- 后端、数据库、账户系统或代理服务器。
- GitHub Copilot 实际账单同步。
- 请求时实时现场运行模型 benchmark。
- 自动抓取或解析 GitHub Docs HTML。
- 雷达图、图表库或外部 CSS 框架。
- 原生 App、推送、多用户协作或云端同步。
- 旧版年度套餐倍率。

## 4. 功能需求

### R1. 模型清单

- 默认只显示当前可用模型。
- 可切换显示已退役模型。
- 当前可用状态由 models.dev 的 `status` 判定；`deprecated` 不进入默认列表。
- 每行必须显示模型名、供应商、输入价和输出价。

### R2. 定价

- 价格单位为美元 / 1M tokens。
- 1 AI Credit 等于 $0.01。
- 缓存输入价默认隐藏。
- 缓存列关闭时不得存在于 DOM，而不能只设置为 `display: none`。

### R3. 参考成本

- 使用固定参考会话：100,000 input + 12,000 output tokens。
- 显示美元成本和 Credits。
- 参考成本不包含缓存折扣。

### R4. Profile

- 高难度权重 20%，通用开发 60%，日常信息 20%。
- 高难度优先使用 Terminal-Bench 4.0，回退 Terminal-Bench 2.0 和 LMArena Agent。
- 通用开发优先使用 SWE-bench Verified，回退 LMArena Webdev。
- 日常信息优先使用 ClawMark，回退 LMArena Document 和 Text。
- 至少两个维度且 coverage 达到 80% 才能输出 Profile。
- 直接 benchmark、legacy benchmark 和 proxy 必须可区分。

### R5. 性价比

- 只有完整 Profile 且至少一个直接维度参与排名。
- 80% 部分 Profile、纯代理 Profile 不进入性价比排名。
- 前三名显示「值选」。
- 无数据或无法防止除零时显示「无法评估」。

### R6. 筛选与排序

- 文本过滤覆盖模型名和供应商。
- 支持名称、供应商、输入价、输出价、缓存价、参考成本、三个 Profile 维度、Profile 和性价比排序。
- 有数据值正常排序；无数据值在升序和降序中都位于末尾。
- Pin 模型始终优先于未 Pin 模型。

### R7. Pin

- 最多 Pin 3 个模型。
- Pin 状态固定在列表顶部。
- Pin 通过 localStorage 跨会话保留。
- 达到上限后其他 Pin 按钮不可用。

### R8. 数据更新与缓存

- 页面提供手动价格更新入口。
- 更新时只持久化规范化后的 Copilot 子集，不缓存完整 models.dev 大响应。
- 更新失败时继续使用上一份数据并显示错误。
- 能力与 Benchmark 数据使用随构建发布的静态快照。

### R9. 能力预测

必须覆盖以下任务：

1. 理解、整理开发文档。
2. 架构发现与定义。
3. 规范定义和实现。
4. 测试与命令行驱动开发。
5. 日常协作情商。

每条预测必须显示：

- 数据源；
- 推断逻辑；
- 置信度。

没有可信证据时必须显示「无可信数据」，不能生成虚构结论。

### R10. 模型匹配

- Copilot 模型与 benchmark/model 名称必须人工确认并精确映射。
- 不采用包含匹配、编辑距离或上一代继承。
- 无法确认时保留 `—`、`无数据` 或「无可信 Profile」。

### R11. 测试固件

- 每个日期化固件必须包含模型、能力和 Benchmark 数据。
- `manifest.json` 必须记录日期、数据来源、capturedAt、规模和 SHA-256。
- 测试必须验证价格字段、目标模型、能力引用、Benchmark 数量和所有文件哈希。
- 测试不得依赖外部网络；线上拉取与离线测试分离。

## 5. 非功能需求

- **技术栈**：Vite、React、TypeScript。
- **架构**：纯前端，无后端。
- **依赖**：直接依赖合计不超过 5 个；当前为 4 个。
- **禁止依赖**：状态管理库、图表库、HTML 解析库、axios。
- **隐私**：不发送用户本地偏好到外部服务；Pin 只存 localStorage。
- **性能**：主页面使用预构建快照；手动更新只缓存模型子集。
- **可访问性**：表格使用语义 HTML，按钮有 label，状态不只依赖颜色。
- **响应式**：页面本身不横向溢出；宽表在自身容器内滚动。
- **可解释性**：派生分数必须能追溯到原始来源、版本和计算逻辑。

## 6. 验收标准

- `./start-web.sh` 能启动可访问的 HTTP 页面。
- `npm run build` 成功。
- 模型、供应商、输入价和输出价可见。
- 缓存列默认不进入 DOM，开关后可显示并可排序。
- Pin 上限为 3，跨刷新保留，并固定在列表顶部。
- 过滤、排序和无数据末尾规则可验证。
- 完整 Profile、80% 部分 Profile 和无 Profile 有清晰不同状态。
- 直接、legacy 和代理能力条视觉不同。
- 无数据模型显示明确文字，不能显示 0 分。
- 五类任务均可查看来源、逻辑和置信度。
- `npm test` 能验证日期化数据固件。
- 页面在桌面和窄屏下可用。
