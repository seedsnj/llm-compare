# Stage 2：信息直观化

实现日期：2026-11-06

## 目标与结果

Stage 2 将原本以数字为主的价格表改成了紧凑的“成本 + 能力”仪表盘：

- 输入、输出和参考成本均增加纯 HTML/CSS 微型条形。
- 主表直接展示 AA Intelligence、LMArena 文本、Webdev、Agent 四项能力信号。
- 默认按开发性价比降序排列，前三名显示绿色「值选」标志。
- Pin、Hover、选中和高性价比使用不同的颜色与形状，不依赖单一颜色表达状态。
- 无数据模型显示明确的「无数据」或「无法评估」，不绘制 0 值条形。
- 没有增加依赖、图表库或外部 CSS 框架。

## 视觉元素

### 价格

1. 输入价、输出价、缓存输入价和参考成本均显示：

   - 原始美元数值；
   - 3–4px 的纯 CSS 微型条；
   - 低、中、高成本的颜色区分。

2. 价格条使用对数刻度：

   ```text
   barPercent =
     log1p(value / activeMin) / log1p(activeMax / activeMin) × 100
   ```

   输入价、输出价和成本分别使用自己的有效模型范围，不跨列比较条长。这样可以让 $0.10 与 $20.00 的差异可见，同时保留原始金额为权威值。

3. 参考成本单元格同时显示：

   ```text
   $0.32 · 32.0 cr
   ```

   其中 `$0.32` 是美元估算，`32.0 cr` 是按 `1 credit = $0.01` 换算的 AI Credits。

4. 参考成本按有效模型的四分位划分为：

   - 低成本；
   - 中成本；
   - 高成本；
   - 极高成本。

### 能力

主表新增四个紧凑能力列：

- AA 智能；
- LMArena 文本；
- LMArena Webdev；
- LMArena Agent。

每个能力单元格显示：

- 原始指标值；
- 指标内的排名；
- 纯 CSS 水平能力条；
- 悬停时通过原生 Tooltip 显示来源模型、发布日期、样本数和归一化范围。

不同能力指标的条长分别计算，不能跨列直接比较。例如 AA 的 `50` 与 LMArena 的 `1500` 不会被放进同一个百分制。

指标提示明确说明：

- AA Intelligence 不是百分制，数字是原始指数。
- LMArena Text/Webdev 是 Bradley–Terry 分数，不是百分制。
- Agent 使用 IPS 分数，可以为负。
- 条长只表示当前快照同指标匹配模型中的相对位置。

### 性价比

性价比列以绿色能力条展示，前三名额外显示「值选」徽标。其余有效模型按数值显示「高效 / 一般 / 偏低」。

Pin 和 Hover 的视觉状态分开：

- Pin：暖黄色行底、实心星、暖色左边框和 `PIN` 标记。
- 普通行 Hover：冷灰蓝行底与蓝色左边框。
- Pin 行 Hover：保持暖色体系，不变成普通 Hover 色。
- 当前选中行：深色内描边；如果同时 Pin，会保留暖底并叠加深色描边。
- 高性价比：绿色徽标与绿色价值条，不使用 Pin 的黄色。

## 综合成本算法

### 参考任务

假设一次典型开发会话需要：

```text
100,000 input tokens
12,000 output tokens
```

输入与输出 token 比例约为 `89:11`，用于模拟日常开发中读取上下文多、生成内容相对少的负载。

### 公式

```text
referenceCost =
  inputPricePer1M × 100,000 / 1,000,000
  + outputPricePer1M × 12,000 / 1,000,000

= inputPricePer1M × 0.1 + outputPricePer1M × 0.012

referenceCredits = referenceCost × 100
```

### 假设与限制

- 综合成本不包含缓存命中折扣。
- cached input 仍作为独立的可选价格列，默认关闭且关闭时整个列不进入 DOM。
- 参考成本不是账单预测；它用于模型之间的统一数量级比较。
- 如果模型价格缺失，原始价格保留 `—`，不参与价格条或参考成本计算。

## 性价比算法

性价比使用 LMArena Webdev 作为能力基准。原因：

- 当前有效模型中 Webdev 覆盖 `24/27`，是 LMArena 里覆盖最好的开发相关信号。
- Webdev 直接测量代码/网页实现，与 GitHub Copilot 的主要使用场景接近。
- 不把 AA、Text、Webdev、Agent 不同尺度的分数相加，避免创造不可核查的“总能力”。

### 能力相对分

先以当前有效模型中所有具有 Webdev 数据的模型为基准：

```text
webdevAbility =
  (webdevRating - activeWebdevMin)
  / (activeWebdevMax - activeWebdevMin)
  × 100
```

### 成本倍数

```text
medianCost = 有 Webdev 数据的有效模型参考成本中位数
costMultiple = referenceCost / medianCost
```

### 性价比指数

```text
valueIndex = webdevAbility / (1 + costMultiple)
```

公式中的 `1 + costMultiple` 会压低高成本模型，同时避免用纯除法造成极端放大的异常值。

### 排名与展示

- 只对具有 Webdev 数据的模型计算性价比。
- 按 `valueIndex` 降序选出前三个有效模型，显示「值选」。
- 价值条按有效模型中的最大 `valueIndex` 归一化到 0–100。
- 无 Webdev 数据的模型显示「无法评估 / 缺少 Webdev」，不进入排名。
- 归一化范围、成本中位数和前三名固定基于当前有效模型集合，不随搜索、Pin 或表格排序改变。
- 显示退役模型时，退役模型可以采用同一基准展示历史参考值，但不会被选为当前「值选」。

当前快照的性价比前三名为：

1. GPT-6.1 Terra：`44.0`
2. Claude Haiku 5.5：`43.0`
3. GPT-6.1 Sol：`42.7`

这些结果会随价格更新重新计算。

## 无数据呈现

### 单项能力缺失

AA、Text、Webdev 或 Agent 任一指标无精确匹配时，对应单元格显示：

```text
无数据
未精确匹配
```

单元格使用灰色虚线和中性文字，不绘制 0 长条形，也不使用缺失数据推算分数。

### 性价比缺失

没有 Webdev 数据时，性价比列显示：

```text
无法评估
缺少 Webdev
```

该模型不进入前三名，也不参与性价比排序的有效值集合。

### 排序

有数据的模型按所选指标排序；无数据模型在升序和降序中都排在最后，避免把缺失误读成最低值。

## 紧凑化

- 供应商从独立列移入模型名称下方。
- 行高从原来的宽松布局压缩到约 49px。
- 单元格内边距、Pin 按钮和字体同步收紧。
- 表头保持粘性。
- 桌面端尽量在一屏宽度内显示价格、能力与性价比。
- 窄屏保持页面本身不横向溢出，只有表格容器允许横向滚动。

## Tooltip 与可解释性

每个派生指标表头都有小型 `?` 提示，说明：

- AA 不是百分制；
- LMArena 分数不是百分制；
- 价格条使用对数刻度；
- 参考成本的 token 假设；
- 性价比只使用 Webdev；
- 无数据不会按零计算。

原始能力 Tooltip 进一步显示指标来源、源模型名、发布日期、排名和样本量。
